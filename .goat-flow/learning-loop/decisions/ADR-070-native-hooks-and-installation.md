# ADR-070: Run managed hooks and consumer installation on Node

**Status:** Accepted
**Date:** 2026-10-11
**Updated:** 2026-11-15

## Context

Managed hooks and installation formerly added Bash discovery and compatibility work to a product whose CLI already needs Node.
The policies use a handwritten parser; Bash did not supply a shell parser. Post-turn scanning already used Node internally.
The maintainer accepted the Node migration on 2026-10-11. This record promotes that decision after the implementation and its separate gates.
ADR-069 was subsequently assigned to capture-row hashing, so this decision uses the next unused number.

## Decision

Author hooks in TypeScript under `src/hooks/` and generate readable `.mjs` files, preserving JSDoc, into `workflow/hooks/` and the installed mirrors.
`scripts/generate-hook-runtime.mjs` owns generated bytes and stamps. Run hook code without compilation or package resolution at invocation.
The consumer floor is Node 20.12.0; this release's compatibility proof also uses Node 24.21.0.
Use built-ins and the existing shipped, licensed vendors. New managed hooks follow the same model.

Keep installation in the TypeScript CLI's existing preview, admission, write-claim, verification and state-publication lifecycle.
`src/cli/installer/apply.ts` owns native file application and the 1.16.0 direct-upgrade floor; older projects upgrade through 1.18.0.

Preserve independent hook choices, trusted-root rules, supported command grammar, provider responses and bounded execution.
Reuse the launcher-selected root without another policy lookup. Keep ADR-066's edited-file scope for Gruff. Stop recovery remains owned by `applyManagedStopRecovery` and its tests;
subsequently accepted recovery exceptions retain their narrower eligibility and incomplete-coverage warnings.

Retain child supervision with enforceable deadlines and owned-process cleanup. A timer in the evaluator's own blocked event loop cannot enforce its deadline.
Worker supervision requires a measured limitation and a separate decision; process consolidation is outside this migration.

Use full JSON decoding, UTF-8 byte limits, ASCII character classes and ASCII folding. Translate POSIX regular-expression semantics explicitly.
Reject invalid UTF-8 hook requests through each hook's failure response. Named, reviewed differences from the former Bash behavior remain explicit.
The shipped policy corpus is the retained oracle after retirement; missing cases and unexplained differences cannot count as successful proof.

Ship installation, registrations, runtime retirement and documentation in one 1.19.0 cutover, without an engine selector or automatic Bash fallback.
Preserve provider descriptor families and process counts under [ADR-053](ADR-053-claude-structured-hook-descriptors.md).
The native installer and hook runtimes do not invoke Bash or Unix text tools. Retain the provider launch and replay transports from ADR-053:
Copilot uses its Bash field on Unix; Antigravity uses `sh -c` on Unix and `cmd /c` on Windows. Those provider transports remain prerequisites.

Switch registrations and stamp final bytes before capturing delivery or activating evidence-gated support.
Windows and WSL require their reviewed live captures; Linux and macOS CI proves compatibility, leaving live delivery unverified.
Captures have no calendar expiry. Relevant provider, configuration, lifecycle, runtime, adapter or registration changes require revalidation.
[ADR-069](ADR-069-capture-rows-pin-the-files-their-hook-loads.md) defines each row's runtime-file pinning.
Local replay and a passing policy corpus do not establish that a provider delivered the result to its model.

## Failure Mode Comparison

| Option | Failure or cost | Decision |
| --- | --- | --- |
| Keep Bash hooks and installation | Retains cross-platform Bash discovery and maintenance | Rejected |
| Node with child supervision | Retains process-start cost while preserving enforceable deadlines and cleanup | Accepted |
| Node worker supervision | Adds startup, interruption and child-cleanup proof obligations without a demonstrated need | Conditional follow-up only |
| Evaluate directly on the supervisor's event loop | A blocked evaluator can prevent its own deadline from firing | Rejected |
| Keep two runtime engines | Adds migration and configuration branches and keeps the Bash dependency | Rejected |
| Adopt Go or Python | Adds runtime or distribution obligations without a demonstrated need | Outside scope |

## Consequences

Managed hooks, installation and goat-flow-owned verification use Node. Repository maintenance scripts may remain Bash.
Git and selected analyzers remain external dependencies. Standard Windows npm analyzer shims resolve to their Node entrypoints;
custom batch wrappers receive an unsupported diagnostic without a shell fallback. Removing Bash does not promise arbitrary shell-language parsing.

Retired runtime files are removed only when their bytes match a stored baseline. Edited or unclassified copies are preserved and reported.
An edited retired hook that remains registered requires an explicit migration decision before switching it or removing its dependencies.
Instruction files may retain old self-test commands until their owner updates them; release guidance names the Node replacements.

## Reversibility

Retirement required an interrupted-installation repair rehearsal using a pinned Node package, preserving user configuration and canonical v2 state.
Installer death may leave write claims: inspect them, confirm the writer has stopped, recover through the public claim command, then reapply the same package.
`test/integration/packaged-hook-install.test.ts` (search: `one real file was published before process death`) retains the archived-CLI recovery proof.

Downgrading to a Bash release is unsupported. Its writer does not know the new registration identities, cannot restore removed runtime files,
and depends on Bash again. Repair with the tested Node package; failure of that repair blocks retirement.
